LOT Tracker 오프라인 테스트 앱 (Windows x64)

버전은 앱 제목과 하단에 표시됩니다. '버전 / 변경 내역' 버튼으로
현재 버전의 수정 사항과 이전 적용 내역을 확인하세요.
이번 v1.0.0부터 버전 번호를 부여합니다. 이전 배포본은 버전 미표시입니다.
검증 ZIP의 app-version.json, status.json 및 로그에도 실행 버전이 기록됩니다.

1. ZIP 파일 전체를 내부망 PC로 복사한 뒤 압축을 해제합니다.
2. LOT Tracker.exe를 실행합니다. exe만 따로 이동하지 마세요.
3. See LOT 파일 선택 · 분석에서 CSV/XLS/XLSX 파일을 함께 선택합니다.
4. 탭에서 공정별 실적, Scrap Summary, Track History, 후속 LOT,
   분할/병합 흐름, 기존 LOT Tracker 보고서를 확인합니다.
5. Excel 보고서 저장을 누르고 폴더를 선택합니다. 보고서 2개가 저장됩니다.

Windows 10/11 x64 및 .NET Framework 4.5 이상이 필요합니다.
Node 런타임과 SheetJS가 포함되어 있어 인터넷, Node 설치, Excel 설치,
브라우저, 웹 서버, 로그인은 필요 없습니다. 네트워크 호출을 하지 않습니다.
보안 정책이 미서명 실행 파일을 차단하면 사내 승인 절차를 이용하세요.

파일당 최대 2MB, 전체 최대 128MB, 최대 500개입니다.
기본 화면과 공정별 보고서는 SMT부터 공정 번호순으로 표시합니다.
기존 고정양식은 비교용이며 M121부터 시작합니다.
SMT RUNID 추적 / SPLIT LOT 목록 / 추가 파일 요청 탭을 확인하세요.
M010 단일 유입 Split의 연결 ID는 RUNID 후보로 표시하며 실제 RUNID 여부는
원본 조회로 확인해야 합니다. 근거 없는 RUNID는 생성하지 않습니다.
추가조회 ID 복사 → See LOT 조회 파일 확보 → 추적 파일 추가 · 재분석 순서로
진행합니다. 이전 입력 복사본을 유지하며 같은 파일명은 새 선택 파일로 갱신합니다.
포함 여부는 LOTID 기준으로 다시 판정합니다. 맵만 있는 경우 See LOT을 요청합니다.
분할 LOT의 See LOT 파일과 PCB 분할/병합 맵도 함께 선택하세요.
모든 관측 공정을 공정별 보고서에 포함합니다.
PART NO는 원본 시작 Split과 RUNID 맵의 연결이 확인된 경우 PROD_ID에서 표시합니다.
여러 MERGE LOT이 있는 RUNID 맵도 지원합니다. 맵과 이벤트 이력을 분리하며,
맵의 행 수나 PCB_ARRAY를 공정 IN/OUT으로 계산하지 않습니다.
RUNID 연결 / RUNID 맵 목록 / RUNID 확인 사항 탭에서 연결 근거를 확인하세요.
맵만 선택한 경우에는 See LOT 이벤트 파일을 함께 선택해야 합니다.
연결되지 않은 맵과 서로 다른 PROD_ID는 확인 사항으로 남기고 품번을 추정하지 않습니다.
SWP 직접 조회, 웹 LOT INFO 저장, 사용자 계정 기능은 포함하지 않습니다.
원본 파일을 변경하지 않습니다. 매 분석마다 앱 폴더의 validation-runs에
날짜-시각-고유번호 폴더와 같은 이름의 ZIP을 함께 자동 보관합니다.
앱의 '검증 기록 폴더' 버튼으로 저장 위치를 열 수 있습니다.
  inputs/ : 선택한 입력 원본의 복사본 (동일 파일명도 번호별 폴더로 보존)
  outputs/ : Excel 보고서 2개, 분석 요약 summaries.json, 화면 결과 result.json
  logs/ : 앱 진행 로그, 분석 단계별 JSONL 로그, 엔진 오류 로그
  request.json : 선택한 원본 경로와 시작 시각
  status.json : 성공/실패 결과 및 갱신 시각
분석은 복사본으로 수행합니다. 로그에는 시각, 처리 단계, 파일 SHA-256,
분석 코드 SHA-256, Node 버전, 오류 메시지 및 스택을 기록합니다.
실패해도 확보된 입력과 로그를 압축합니다. 생성되지 않은 출력은 없습니다.
Excel을 추가 저장하면 저장 경로 또는 저장 실패 로그도 ZIP에 갱신합니다.
기록은 앱 종료 후에도 남습니다. 앱 폴더에 쓰기 권한과 저장 공간이 필요합니다.
ZIP 생성 실패 시 경고를 표시하고 검증 폴더를 보존합니다.
강제 종료/전원 차단 시 ZIP이 완성되지 않을 수 있으며 작성된 폴더와 로그는 남습니다.

개발: 저장소 루트에서 powershell -File desktop\build.ps1 실행.
desktop/engine의 고정된 LOT 분석 모듈을 복사합니다. 루트의 웹 엔진과 다릅니다.
분석 로직 수정 후 다시 빌드하세요. 개발 인수인계는 desktop/HANDOFF.md를 읽으세요.
배포 시 desktop/release.json의 version과 changes를 갱신하고 이전 내역을
previousChanges에 보존하세요. 수정 배포마다 버전을 올립니다.
버그 수정은 patch, 기능 추가는 minor, 호환성이 바뀌는 변경은 major를 올립니다.
빌드가 실행 파일 속성, 내장 변경 내역, release.json, 배포 ZIP 이름을 함께 생성합니다.

v1.0.3 검증 시 유의사항:
- 번호 연속성으로 부모 LOT을 추정하지 않습니다. UUID 이름이 남으면 실제 LOTID와 연결 이력을 확인하세요.
- 서로 대응하는 Split 이벤트의 시각·공정·수량이 일치할 때만 UUID 파일의 부모 LOTID를 복원합니다.
- Merge는 전후 수량으로 보내는 LOT과 받는 LOT을 구분합니다. 근거가 부족하면 방향 확인 필요로 표시합니다.
- 전량 이동 후 보내는 원래 LOT의 Terminated 상태를 보존합니다.
- Split 구분 000은 SMT 투입 RUNID, 001~ZZZ 중 사용 금지 값은 미확정입니다. 번호 공백을 오류로 보지 않습니다.
- 현재는 파일 입력 방식입니다. 향후 내부망 SQL 조회를 연결할 분석 경계를 유지하며 DB 접속은 아직 없습니다.
