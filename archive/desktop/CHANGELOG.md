# LOT Tracker Offline 개발 이력

## 1.0.3 — 2026-09-25

- 자식의 생성 Split과 부모의 대응 Split이 시각·공정·수량까지 일치할 때 UUID 파일의 부모 LOTID를 복원. 번호 배열만으로는 계속 추정하지 않음.
- Merge 이벤트의 이전·이후 수량으로 유입과 유출을 구분. 근거가 모자라면 방향을 만들지 않고 `병합 방향 확인 필요`로 표시.
- 자식 LOT의 생성 Split을 해당 LOT의 후속 분할로 중복 표시하지 않고, 이후 공정의 실제 Split은 유지.
- 제공된 2개 실제 이력에서 부모 1200 전량 분할과 종료, 선택 LOT의 199개 유입 Merge 및 이후 200 분할, 불량 반영 후 현재 수량을 대조. 실제 파일은 저장소에 포함하지 않음.

## 1.0.2 — 2026-09-24

- 번호 연속성만으로 UUID 파일의 부모 LOTID를 생성하던 추정 제거. ASSYLOT 및 상호 이벤트 근거는 유지.
- Merge를 원래 LOT에서 대상 LOT으로 표시하고 루트 LOT의 Merge도 포함. 병합 후에도 이전 Split 관계 보존.
- 전량 이동 시 원래 LOT 종료, 부분 이동 시 잔량을 구분. 실제 종료 상태는 원본 이력을 유지.
- LOTID 자리 규칙과 금지값 미확정, 파일/향후 SQL 입력의 분리 기준은 저장소의 desktop/LOT-RULES.md와 desktop/INPUT-CONTRACT.md 참고.


## 1.0.1 — 2026-09-22, 다중 병합 RUNID 맵 오류 수정

- 증상: 기존 이벤트 파일 분석은 성공하지만 RUNID XLS 21개를 추가하면 `Mixed PCB split / merge map`으로 중단.
- 원인: 파서가 한 맵에 MERGE_LOT 하나만 허용. 제공된 첫 파일은 분할 400행이 여러 병합 대상으로 연결되는 정상 구조였음.
- 수정: 여러 병합 대상과 원본 행을 보존하고 RUNID 맵을 이벤트 LOT 집계에서 분리. 시작 Split과 맵의 명시적 직접/경유 연결이 있는 경우만 PROD_ID 연결. 상충하는 품번은 추정하지 않음.
- UI/보고서: RUNID 연결·맵 목록·확인 사항을 추가. 이미 연결된 맵 재요청을 해제하고, 맵으로 알 수 없는 선행 SMT/M033 이벤트 이력 요청은 유지.
- 환경 호환: GitHub Windows 검증에서 발견한 stdin UTF-8 BOM JSON 오류도 수정.
- 재검증: 제공된 62개 파일을 이벤트 41 LOT + RUNID 맵 21개로 분석. 38 LOT의 맵 연결·품번 확인, 나머지는 미확정 상태 유지. 공정 이력이 없는 맵을 실적으로 합산하지 않음.
- 가상 400행 XLS/다중 MERGE_LOT, 직접·경유·미연결·품번 충돌, 맵만 선택, 누락 선행 이력, BOM 입력 회귀 테스트 추가. 원본 업무 파일은 GitHub에 올리지 않음.

## 1.0.0 — 2026-09-22, 최초 번호 부여 배포

- 앱 제목/하단, 버전 창, 실행 파일 속성, 배포 ZIP 이름에 버전 표시.
- 내장 변경 이력과 빌드 시각을 표시하고 검증 ZIP 및 실행 로그에도 기록.
- 이전 배포는 번호가 없었으므로 과거 버전 번호를 소급해서 만들지 않음.

## 버전 표시 전 — 2026-09-22

사용자 요청 순서로 기록합니다. 아래 항목은 별도 과거 릴리스나 Git 커밋이 존재했다는 의미가 아닙니다.

1. **오프라인 앱:** 내부망 테스트를 위해 WinForms 화면, Node 분석 엔진, 런타임 포함 ZIP과 Excel 저장 구현.
2. **검증 기록:** 실행마다 입력/출력/로그 ZIP 자동 보관. 상세 오류, 파일/코드 SHA-256, 타임스탬프 추가. 실패 시 확보된 자료 보존.
3. **실사용 기록 점검:** 41개 파일이 오류 없이 분석되고 입력 해시가 일치함을 확인. 정상 종료와 업무 계산 정확성을 구분해 안내.
4. **공정 표시·추적 보완:** 고정 양식이 M121부터 시작하는 혼선을 명시하고 전체 공정은 SMT부터 정렬. SMT RUNID 후보, SPLIT LOT, 추가 파일 요청 탭과 ID 복사/추가 파일 재분석 제공. 오프라인 파일 한도를 500개/128MB로 확장.

## 개발 보관 — 2026-09-22

- 최신 웹 main에서 분기한 전용 브랜치와 PR에 앱, 동결 분석 엔진, 테스트, 라이선스, 인수인계 문서를 보관.
- 기존 웹 RUNID 개발과 로컬 후보 판별의 차이를 문서화.
- 실행에 쓰인 1.0.0 앱 동작은 유지하고, 빌드는 동결 엔진과 정확한 Node 버전을 사용하도록 명시.
- 패키징을 허용 파일 목록으로 제한해 업무 검증 자료가 배포 ZIP에 들어가는 것을 방지.
- 가상 데이터 기반 Windows 검증 워크플로 추가. GitHub Actions 결과와 PR 검증 결과를 별도 확인.
