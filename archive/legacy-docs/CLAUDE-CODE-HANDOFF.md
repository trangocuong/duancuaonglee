# Claude Code 비상 작업 인계 템플릿

이 문서는 현재 비상 인계가 발생했다는 기록이 아니라, `AGENTS.md`의 사용량 임계치에 도달했을 때 갱신할 재사용 템플릿이다. 평상시에는 아래 자리표시자를 실제 상태로 오인하지 않는다.

## 사용 조건

- 사용량 임계치와 단계별 조치는 항상 최신 `AGENTS.md`를 따른다.
- 임계치에 도달하면 새 구현을 시작하지 않고 실행 중인 파일 쓰기·빌드·테스트만 안전하게 종료한다.
- 상태를 기록하기 전에 `git status --short`, 현재 브랜치, 전체 HEAD를 다시 확인한다.
- 과거 문서의 성공 기록을 이번 세션에서 실행한 결과처럼 옮기지 않는다.
- 이 문서 갱신을 이유로 `main` 병합, 운영 배포 또는 DB 변경을 새로 실행하지 않는다.

- **작업 트리**: `[clean / dirty]`
- **원격 또는 PR 상태**: `[확인한 경우에만 기록, 미확인이면 미확인]`

### 미커밋 변경

`git status --short`가 비어 있으면 `없음`이라고 기록한다. 변경이 있으면 각 파일을 다음 형식으로 작성한다.

- `[상태 코드] 경로` — `[완료/진행 중/미검증]`, `[변경 목적과 안전한 재개 지점]`

사용자 변경과 이번 세션 변경을 구분할 수 없으면 추측하지 말고 `소유 미확인`으로 표시한다.

## 5. 영향과 금지사항

- **제품 동작 변경**: `[있음/없음 및 해당 제품·버전]`
- **운영 배포 영향**: `[없음/확인 필요/구체적 사실]`
- **DB 변경 영향**: `[없음/확인 필요/구체적 사실]`
- **실제 업무 자료 사용 여부**: `[없음/있음, 내용·경로·시크릿은 기록하지 않음]`
- `main` 병합, 운영 배포 및 DB 변경은 사용자의 별도 지시와 필수 검증 없이 수행하지 않는다.
- 시크릿, 실제 업무 파일, 내부망 경로 및 검증 ZIP 내용은 이 문서나 Git에 기록하지 않는다.
- 동일한 ZIP이나 동일 소스를 다른 세션에서 다시 분석하지 말고 기존 검증 기록을 먼저 확인한다.
- 웹·Windows·HTML 제품을 서로 덮어쓰거나 하나의 검증 결과로 다른 제품까지 검증됐다고 간주하지 않는다.

## 7. Claude Code에 붙여넣을 프롬프트

```text
이 저장소의 작업을 안전하게 이어서 진행해 주세요.

먼저 저장소 루트의 AGENTS.md, DEVELOPMENT-STATUS.md와 CLAUDE-CODE-HANDOFF.md를 읽고, 현재 작업 대상에 하위 AGENTS.md가 있으면 해당 지침도 확인하세요. 문서의 기록을 그대로 믿지 말고 git status --short, 현재 브랜치와 전체 HEAD를 실제 상태와 대조하세요. 기존 미커밋 변경은 보존하고 소유가 불분명한 변경을 되돌리지 마세요.

인계 문서의 '다음 단계' 첫 항목부터 진행하되, 완료·진행 중·미검증 상태를 구분하세요. 과거 성공 기록을 이번 실행 결과로 표현하지 말고 관련 단위 테스트부터 실행한 뒤 최종 단계에서만 필요한 전체 검증을 수행하세요.

사용자의 별도 지시 없이 main 병합, 운영 배포 또는 DB 변경을 하지 마세요. 시크릿, 실제 업무 파일, 내부망 경로 및 검증 ZIP을 Git에 추가하지 마세요. 동일한 ZIP이나 동일 소스는 기존 검증 기록을 확인한 뒤 중복 분석하지 마세요.
```

## 갱신 완료 확인

- [ ] 시각과 사용량을 실제 값으로 기록했다.
- [ ] 브랜치, 전체 HEAD 및 `git status --short`를 다시 확인했다.
- [ ] 미커밋 파일별 상태와 재개 지점을 기록했다.
- [ ] 이번 세션에서 실제 실행한 검증만 기록했다.
- [ ] 실패와 미실행 검증을 분리했다.
- [ ] 배포·DB·실제 자료 영향을 기록했다.
- [ ] 다음 한 단계를 구체적으로 작성했다.
- [ ] `main` 병합·운영 배포·DB 변경을 인계 목적으로 실행하지 않았다.
