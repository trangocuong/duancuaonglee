# 입력과 분석의 경계

현재 파일 검증과 향후 내부망 SQL 조회는 같은 분석 규칙을 사용한다. SQL 연결은 아직 구현하지 않았다.

1. 수집: 지금은 analyze.mjs가 파일 바이트를 읽는다. 향후 조회 어댑터는 LOTID 매개변수로 이벤트와 RUNID 맵을 조회한다.
2. 정규화: 파일 파서 summarizeSeeLotWorkbook은 LOT 요약을 만든다. SQL 어댑터도 동일한 의미의 이벤트/맵으로 정규화한다. DB 열 구조 확인 전 임의 매핑을 만들지 않는다.
3. 관계 분석: resolveTrackerSummaries 및 connectRunMaps는 파일 시스템이나 DB 접속 없이 정규화된 요약을 입력받는다. 조회 및 접속 로직을 이 함수에 넣지 않는다.
4. 보고서: 공정 보고서, 추적 목록, Split/Merge 계보는 같은 정규화 결과를 사용한다.

입력 의미:
- 이벤트에는 LOTID, 원본 이벤트 ID(있을 때), 이벤트명, 시각, 공정, 수량, 변경 수량, 관련 LOTID 및 원본 출처가 필요하다.
- 원본 이벤트 정렬·Cancel 제외 규칙은 파일 파서와 일치해야 한다. 동일 시각의 순서는 원본 근거 없이 재정렬하지 않는다.
- RUNID 맵은 공정 이벤트와 별도 입력이다. 맵을 생산 실적으로 합산하지 않는다.
- Merge는 현재 LOT에서 관련 대상 LOT으로 이동하는 관계다. 종료 여부는 원본 종료 이력을 보존한다.
- 파일 입력 경로는 SQL 연결 후에도 재현 검증용으로 유지한다. 조회 시각·조건과 원본 식별을 기록하며 인증정보는 결과에 포함하지 않는다.

향후 SQL 어댑터의 완료 조건: 동일 자료를 파일과 DB로 각각 입력해 LOT 관계·수량·보고서가 일치하는 회귀 검증. DB 종류·권한·스키마·조회문 확인이 선행되어야 한다.
