# Offline Web 변경 이력

## 1.0.6 — 2026-09-25

- UUID 이름의 See LOT 이벤트 파일에서 M010 `ISSUE_VMS1_VMDL`, 종료, 전체 Split 수량이 일치하고 모든 자식 LOT의 5~7자리만 다를 때 해당 자리를 `000`으로 바꾼 값을 SMT 투입 RUN ID로 인식.
- 위 근거가 완전한 경우 자식 LOT 전체를 추가 요청하지 않고 RUN ID 한 건의 PMS 정보(PART NO·FAB·TIER·OPT·투입수량)를 요청. 수량 불일치·일반 파일명·서로 다른 LOT 계열은 기존처럼 자동 확정하지 않음.
- TrackIn·TrackOut이 없어도 SMT 공정을 선택해 화면·Excel·검증 ZIP을 만들고, 추적 탭과 경고에 PMS 확인 필요를 표시.

## 1.0.5 — 2026-09-25

- 사용자 지정 고정 표를 `LOT 공정표` 화면 탭과 Excel 첫 시트로 추가. PART NO·LOT NO·FAB·TIER·OPT, M010-M015, M033, SPLIT LOT, M050, M055 1/2차, M060을 한 행 계층으로 표시.
- PCB 분할/병합 맵의 2D 바코드에서 검증 가능한 고정 위치의 FAB·TIER·OPT를 읽고, PCB_ARRAY 합계를 M010-M015 수량에 사용. 값이 일치하지 않으면 빈칸으로 두어 임의 판정하지 않음.
- 원 LOT은 첫 행에 표시하고 실제 Split 자식은 SPLIT LOT 후속 행으로 배치. 공정이 없는 원판 이력과 RUNID/PCB 맵은 별도 LOT 실적으로 표시하지 않음.
- `H094000639 seelot.xls`처럼 설명이 붙은 파일명은 첫 LOTID 토큰만 사용. 동적 공정 선택 보고서와 추적 탭은 유지.

## 1.0.4 — 2026-09-25

- 자식의 생성 Split과 부모의 대응 Split이 시각·공정·수량까지 일치할 때 UUID 파일의 부모 LOTID를 복원. 번호 배열만으로는 계속 추정하지 않음.
- Merge 전후 수량으로 유입·유출 방향을 구분하고 근거가 모자란 관계는 `병합 방향 확인 필요`로 표시.
- 생성 Split이 자식 분할로 중복되던 계보를 바로잡고 이후 실제 Split은 유지.
- 제공된 실제 2개 파일을 Chrome 오프라인 재생 대상으로 추가 검증하며, 실제 파일과 결과 ZIP은 Git에 포함하지 않음.

## 1.0.3 — 2026-09-24

- 단일 HTML 통합 과정에서 화면 연결이 빠졌던 공정 선택 기능을 복구. 관측된 공정을 기본 선택하고 전체 선택·전체 해제·선택 적용을 제공.
- 공정 선택을 화면의 공정별 보고서, Scrap Summary, Track History, Excel 및 검증 ZIP에 동일하게 반영.
- 요청에 따라 `기존 고정양식 (M121부터)` 탭과 별도 고정양식 Excel을 HTML 제품에서 제거. Windows 제품은 변경하지 않음.
- 공정을 하나도 선택하지 않은 상태에서는 기존 보고서를 유지하고 오류 안내만 표시.

## 1.0.2 — 2026-09-24

- 번호 연속성만으로 UUID 파일의 부모 LOTID를 생성하던 추정 제거. ASSYLOT 및 상호 이벤트 근거는 유지.
- Merge를 원래 LOT에서 대상 LOT으로 표시하고 루트 LOT의 Merge도 포함. 병합 후에도 이전 Split 관계 보존.
- 전량 이동 시 원래 LOT 종료, 부분 이동 시 잔량을 구분. 실제 종료 상태는 원본 이력을 유지.
- LOTID 자리 규칙과 금지값 미확정, 파일/향후 SQL 입력의 분리 기준은 저장소의 desktop/LOT-RULES.md와 desktop/INPUT-CONTRACT.md 참고.


## 1.0.1 — 2026-09-22

- 사용자가 전달한 단일 HTML 앱을 기존 GitHub 인수인계 브랜치에 통합. WinForms 최신 수정은 보존.
- 버전 원본을 release.json으로 통합하고 빌드 시각 대신 배포일을 사용해 재현 가능한 빌드로 변경.
- SheetJS 0.18.5 → 0.20.3, 라이선스 보관.
- RUNID XLS/XLSX를 메타데이터로 우선 분류해 여러 MERGE_LOT 맵의 파싱 오류 해결. 원본 시작 Split으로 연결하고 여러 RUNID 후보가 충돌하면 임의로 선택하지 않음.
- 연결된 RUNID 맵 재요청 제거. 공정 이력이 없으면 선행 LOT의 이벤트 파일 요청은 유지. PART NO 안내를 실제 연결 근거에 맞춤.
- 실행 중 입력 변경 차단, 실패 후 이전 결과 저장 버튼 비활성화, 오류 스택 보관.
- 단위 테스트와 실제 브라우저 E2E/ZIP 보관/정리/네트워크 차단/재현 빌드 검증을 소스로 기록.

## 1.0.0 — 전달받은 작업

RUNID 직접/간접 연결 이식, 단일 HTML UI, SheetJS/JSZip/SHA-256 내장, Excel 다운로드, 실행 로그 및 검증 ZIP 제공. 최근 5회분의 입력/결과만 보존하고 이전 회차는 로그를 남기는 정책 포함. 이전 세션의 E2E 스크립트는 전달받지 않았으므로 통합 시 다시 작성해 검증했습니다.
