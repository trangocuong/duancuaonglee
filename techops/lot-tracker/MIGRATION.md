PC의 실시간 파일 읽기·명령 실행 도구가 없고 클라우드 환경이 pending/offline이어서, 복원 결과와 현재 PC 파일의 바이트 단위 일치는 확인하지 못했다. 로컬 원본이나 미커밋 파일을 삭제하지 않았다. 실제 업무 파일이나 검증 ZIP은 복원·커밋하지 않았다.

보고서 수정에는 미선택 LOT의 빈 상세 행 생성 방지, 명시적 ModifyAttrh의 EVAL/TIER/OPT 반영, 검증된 SMT/PMS 묶음, 82열 단일 시트와 중복 표 제거가 포함된다. Windows 1.0.4의 네이티브 포장·자동 로컬 ZIP 기록은 HTML 기능으로 옮기지 않는다. 브라우저에서는 ZIP 다운로드와 최근 5회 원본 보관을 유지한다.

기존 고정 공정표 테스트는 최신 단일 82열 보고서 정책으로 갱신했다. PMS 바코드 위치만으로 TIER/OPT를 채우던 오래된 기대값 대신, 원본 ModifyAttrh 근거를 검사하며 원본이 없으면 빈칸을 유지한다. 이 기대값 변경은 계산 오류를 숨기는 수정이 아니라 이미 로컬 v1.1.2에서 변경된 속성 정책의 반영이다.

`lot-tracker/`가 앞으로의 유지관리 경로다. 보고서와 계보 추적은 한 파일·한 버전·한 파일 선택을 공유하며, 서로 다른 계산 범위 때문에 내부 실행 영역을 격리한다. 기존 Windows/Offline 소스는 통합 검토와 회귀 비교를 위해 역사 자료로 남기고 자동 빌드 대상에서 제외한다. 운영 workmanager, Cloudflare 설정과 DB는 변경하지 않는다.
