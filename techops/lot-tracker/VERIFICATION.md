## v1.2.9: 수율 자릿수와 미리보기 안내

사용자 요청: 수율이 100%이면 소수점 1자리, 100% 미만이면 2자리로 표시합니다.

- 화면 표·'텍스트로 복사'·Excel에 같은 규칙을 적용합니다(1 → 100.0%, 0.99565 → 99.57%). 100%를 넘는 값도 1자리입니다.
- Excel은 원본 v3 `styles.xml`에 이미 있는 셀 서식 19(내장 `0.00%`, 글꼴·채우기·테두리·정렬은 기존 수율 서식 17과 같음)를 100% 미만 수율에 씁니다. 셀 값은 반올림하지 않은 비율 그대로이고 서식 파일은 바꾸지 않았습니다.
- 사용자가 엔지니어 PC에서 버튼이 모두 비활성인 화면을 보냈는데, 파일을 내려받아 열면 정상이라고 확인했습니다. 내려받지 않고 연 미리보기가 안쪽 보기의 스크립트를 실행하지 못한 경우입니다. 이때 머리글 안내를 "미리보기 창에서 열었다면 파일을 내려받아 Chrome이나 Edge로 여세요"로 바꿨습니다.

실행 검증: 빌드 재현, 보고서 회귀 23건, Trace 회귀 28건, 수량 속성 20 seed × 1,000 × 20, 내장 v3 양식 103조건(100% 미만 서식·값 4건 추가), Chromium 통합 검사(100% 미만 화면 `90.00%` 추가) 통과. 추가한 화면·Excel 검사는 수정 전 코드에서 실패합니다. 실제 입력 8개로 만든 Excel은 값이 같고 100% 미만 수율 셀(병합된 칸 포함 21칸)의 서식만 바뀌었습니다.

## v1.2.7: 격리된 미리보기에서 동작

사용자가 Claude 앱의 HTML 미리보기에서 v1.2.6을 열자 "준비 중…"에서 멈추고 `Blocked a frame with origin "null" from accessing a cross-origin frame` 오류가 났습니다. 미리보기는 HTML을 보안 격리된 프레임(불투명 origin)에서 실행하는데, 머리글이 LOT 보고서·계보 추적 프레임의 창 객체를 직접 읽고 있었기 때문입니다. 같은 구조인 v1.2.3·v1.2.5도 같은 조건에서 똑같이 멈추는 것을 재현했습니다. Chrome/Edge에서 파일을 직접 열 때는 문제가 없었습니다.

- 머리글과 두 보기 사이의 연결(준비 알림, 실행 중 잠금, 파일 전달, 초기화, 언어 변경)을 `postMessage`로 바꿨습니다. 메시지는 부모 창 또는 자기 보기 프레임에서 온 것만 받습니다.
- 보기가 5초 안에 준비를 알리지 않으면 머리글에 오류를 표시합니다.
- 미리보기가 다운로드를 허용하지 않으면 Excel·검증 ZIP 저장은 미리보기 설정에 따라 막힙니다. 이때는 HTML을 내려받아 Chrome/Edge로 여세요.

실행 검증: 빌드 재현, 보고서 회귀 23건, Trace 회귀 28건, 수량 속성 20 seed × 1,000 × 20, 내장 v3 양식 99조건, Chromium 통합 검사(격리 프레임 `allow-scripts allow-downloads`에서 파일 추가·분석·언어·Excel 저장·계보 추적과 오류 없음 확인 추가, 수정 전에는 실패) 통과. 받은 실제 입력 8개로 `allow-scripts`만 허용한 격리 프레임에서도 분석·언어 전환·추적이 동작했고, 직접 연 결과 Excel 시트는 v1.2.5와 바이트 단위로 같습니다.

## v1.2.6: 화면 언어 선택

계보 추적에만 있던 한국어 / Tiếng Việt 선택을 상단 머리글로 옮겨 머리글·LOT 보고서·계보 추적이 한 설정을 따르게 했습니다. 업무관리 사이트에 들어가면 사이트 언어를 따르게 바꿀 예정이므로, 그 전까지 HTML 단독 사용을 위한 설정입니다.

- 고른 언어는 이 브라우저의 localStorage에 기억하고, 저장할 수 없는 환경에서는 한국어로 시작합니다.

## v1.2.5: MERGE 방향 부호

사용자가 MERGE 방향을 QTY 칸의 부호로 표시하도록 정했습니다(들어온 합병 `+54`, 나간 합병 `-34`).

- 판정: See LOT의 QTY는 각 이벤트 뒤 LOT 수량이므로 바로 앞(더 오래된) 이벤트의 QTY가 합병 전 수량입니다. 합병 후 = 합병 전 + 이동 수량이면 `+`, 합병 전 - 이동 수량이면 `-`입니다. 이 계산이 맞지 않거나 값이 없으면 부호 없이 표시합니다.
- 검증된 SMT 묶음의 M033 MERGE는 배열 LOT이 부모 LOT으로 들어온 것이므로 `+`입니다.
- SPLIT QTY는 지금처럼 부호 없는 숫자입니다.
- Excel: 부호 있는 MERGE QTY는 부호가 보이도록 텍스트 셀로 저장하고(기존 가운데 정렬 본문 서식), 해당 QTY 열에 '텍스트로 저장된 숫자' 경고를 끄는 `ignoredErrors`를 둡니다. 원본 `styles.xml` 등 서식 파일은 그대로입니다.
- 실제 자료 결과: 8건 모두 부호가 붙었고 양쪽 기록이 맞습니다(루트 `+140` ↔ 상세 `-140`). 끝에 0이 되는 합병은 모두 `-`, 수량이 늘어난 합병은 모두 `+`입니다. 공정 실적은 사용자가 보낸 v1.2.3 결과 Excel과 같습니다.

실행 검증: 빌드 재현, 보고서 회귀 23건(합병 방향 판정 1건 추가), Trace 회귀 28건, 수량 속성 20 seed × 1,000 × 20, Chromium 통합 검사, 내장 v3 양식 99조건(부호 텍스트·서식·경고 끄기 4건 추가, 내보내기 수정 전에는 실패) 통과. 받은 입력 8개를 v1.2.5 HTML에 넣어 Chromium에서 Excel까지 받아 확인했습니다.

## v1.2.4: 상세 LOT 변경 이력 행

사용자가 v1.2.3으로 만든 실제 결과 Excel과 같은 실행의 검증 ZIP(MES 7개·PMS 1개)을 받아 원인을 확인했습니다. 수정 전 엔진은 받은 Excel의 변경 이력 열을 그대로 재현했습니다.

- 문제: 상세 LOT가 다시 분할되면 자식 LOT의 탄생 기록(자식 파일의 `Split`, 상대=부모)이 부모 행에 부모 자신의 LOT ID로 나왔습니다. 상세 LOT와 루트 사이의 `Merge`도 상세 행에 상세 LOT 자신의 ID로 나오고, 루트 행에는 빠졌습니다.
- 원인: 기록의 상대 LOT가 상세 LOT이면 종류와 관계없이 그 상대 행에 넣었습니다.
- 수정: 상세 LOT로 나가는 분할(`isOutgoingSplit`)만 그 상세 LOT의 탄생으로 보아 해당 행에 둡니다(기존과 같이 `SPLIT <그 LOT> 수량`). 그 밖의 기록은 기록이 나온 LOT의 행에 상대 LOT ID로 표시합니다. 같은 분할의 양쪽 기록은 기존 규칙대로 한 번만 표시합니다.
- 실제 자료 결과: 상세 LOT 행의 자기 ID `SPLIT` 2건이 없어지고, 그 행에는 자기 탄생 분할과 루트로 나간 `MERGE`만 남습니다. 루트 행에 들어온 `MERGE`가 추가됩니다. 6개 LOT의 공정 실적(EQP·IN·OUT·SCRAP·FAIL·YLD)은 받은 Excel과 같습니다. 본문은 25행에서 24행이 되었습니다.
- `MERGE`의 들어옴·나감 방향은 v1.2.5에서 표시합니다.

실행 검증: 빌드 재현, 보고서 회귀 22건(새 합성 회귀 1건은 수정 전 엔진에서 실패), Trace 회귀 28건, 수량 속성 20 seed × 1,000 × 20, Chromium 통합 검사와 내장 v3 양식 95조건 통과. 받은 입력 8개를 v1.2.4 HTML에 넣어 Chromium에서 Excel까지 받아 위 결과를 확인했습니다. 실제 입력·결과·검증 ZIP은 Git이나 HTML에 넣지 않았습니다.

## v1.2.3: 양식 선택 제거

실제 첨부를 읽고 비교했습니다. `LOT Tracer Result 20261002.xlsx`는 기존 프로그램 출력이고 `LOT Tracer Result v3.xlsx`는 요청 양식입니다.

v1.2.2의 외부 기준 양식 선택 방식은 실제 v3의 열 구성·수식을 지원하지 못했습니다. 이 기능을 제거하고 업무 값을 비운 v3 서식을 HTML 안에 포함했습니다. 사용 흐름은 MES·PMS 파일 추가 → 분석 → Excel 다운로드입니다.

- 원본 `Sheet1`, B2:CE3의 두 줄 머리글과 A열·1행 여백을 유지합니다.
- identity 7열, SMT·M111 각 6열, 나머지 공정 각 9열로 총 82열입니다. 9열 공정에서는 Mutation·Change LOT·QTY가 실적 6열보다 먼저 나옵니다.
- 머리글 병합·열 너비·스타일·테마·페이지 설정을 원본에서 보존했습니다.
- 분석된 LOT의 변경 이력은 이벤트별 행으로 표시하며 같은 실적과 RUNID identity를 안전하게 병합합니다. 다른 수량이나 값은 병합으로 숨기지 않습니다.
- 공정별 이벤트의 실제 STEP을 사용하고 기존 M100→M087, M165→M164 이동을 제거했습니다. 실제 시각·수량·양끝 LOT·공정이 모두 일치하는 reciprocal 기록만 중복 제거합니다.
- 수율의 원본 공식을 유지하면서 비율을 소수점 한 자리로 반올림하던 오류를 제거했습니다. 99.8%의 정밀도를 유지합니다.
- 내장 XLSX의 원본 업무 값·공유 문자열 캐시·수식·메모·작성자 정보·외부 관계를 제거했습니다. 검증 ZIP에 별도 기준 양식 사본을 넣지 않습니다.

## 남은 확인
